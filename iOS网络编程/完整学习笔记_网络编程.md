## 一、语言基础 — OC 语法

### 1.1 Block（匿名函数 / 闭包）

**概念：** `^返回值类型(参数列表){ 代码 }`，一个"可以保存起来、晚点再执行的代码块"。网络回调的核心——所有请求结果都通过 Block 返回。

**代码示例：**

```objc
// 最简 Block
^{ NSLog(@"被执行了！"); };

// 带参数和返回值的 Block
^(int a, int b) { return a + b; };
```

**问答：**

- Q: `^(NSData *data, NSURLResponse *response, NSError *error)` — Block 什么时候执行？
- A: 网络请求发出去后，代码继续跑（不阻塞），等服务器数据回来（1~3 秒后），系统自动调这个 Block。
- Q: Block 里的 `data`、`response`、`error` 数据从哪来？
- A: 系统自动填的。`data` 是服务器返回的二进制数据，`response` 是 HTTP 响应信息，`error` 是错误信息（成功时为 nil）。
- Q: `if (completion)` 是判断 1 还是 0？
- A: 不是判断数值，是判断 **Block 指针是否为空**。调用方可能传 nil（表示"不关心结果"），对 nil Block 调用会直接崩溃，所以必须先判空。
- Q: 调用方传的 Block 通过 `completion(YES, users, nil)` 传给了谁？
- A: 回传给调用方。数据不通过 `return` 返回，而是通过 Block 的参数回传。调用方的 Block 里 `^(BOOL ok, id result, NSError *err)` 这三个参数就拿到了数据。

**Block 和 C 语言函数指针类比：**

```c
// C 语言
void (*funcPtr)(int) = someFunction;
if (funcPtr) funcPtr(42);   // 指针不为 NULL 才调用

// OC（完全一样）
NetworkCompletionBlock block = someBlock;
if (block) block(YES, users, nil);  // Block 不为 nil 才调用
```

### 1.2 typedef 自定义 Block 类型

**概念：** 给 Block 起别名，和 C 语言 `typedef` 给函数指针起别名一个道理。

**代码示例：**

```objc
// 不用别名：每次都要写完整签名（又长又乱）
- (void)fetchUsersWithCompletion:(void (^)(BOOL, id, NSError *))completion;

// 用了别名：简洁清晰
typedef void (^NetworkCompletionBlock)(BOOL success, id _Nullable result, NSError * _Nullable error);
- (void)fetchUsersWithCompletion:(NetworkCompletionBlock)completion;

// 下载专用 — 两个不同类型
typedef void (^DownloadProgressBlock)(double progress);          // 进度回调
typedef void (^DownloadCompletionBlock)(BOOL, NSString *, NSError *);  // 完成回调
```

### 1.3 单例模式 + dispatch_once

**概念：** 确保一个类全局只有一个实例。`static` 变量保证存储唯一，`dispatch_once` 保证初始化代码只执行一次且线程安全。

**代码示例：**

```objc
+ (instancetype)sharedManager {
    static NetworkManager *instance = nil;    // static 局部变量，程序生命周期内只初始化一次
    static dispatch_once_t onceToken;          // 标记变量（0 = 还没执行，-1 = 已执行）
    dispatch_once(&onceToken, ^{
        instance = [[self alloc] initPrivate]; // 大括号里只执行一次
    });
    return instance;
}
```

**问答：**

- Q: `static` 是什么意思？"只初始化一次"怎么理解？
- A: `static NetworkManager *instance = nil;` 里的 `= nil` 只在第一次调用时执行，之后调用跳过赋值语句，直接使用上次的值。类比 C 语言 `static int count = 0;`。
- Q: `dispatch_once` 为什么需要？只有 `static` 不够吗？
- A: `static` 只保证变量地址不变，不保证赋值操作只执行一次。两个线程同时调用 `sharedManager` 时可能同时执行 `= [[self alloc] initPrivate]`，创建两个实例。`dispatch_once` 内部有线程锁，保证绝对只执行一次。
- Q: 为什么设两个 `init` 方法（`initPrivate` 和重写 `init`）？
- A: `initPrivate` 是真正的初始化，只给 `sharedManager` 内部用。重写 `init` 让它抛异常，防止外部用 `[[NetworkManager alloc] init]` 破坏单例。
- Q: `@throw` 是什么？系统自带的吗？
- A: 是，OC 的抛异常语句。`@throw [NSException exceptionWithName:reason:userInfo:]` — `userInfo:nil` 表示不需要附加信息字典。

### 1.4 类方法（+）vs 实例方法（-）

**概念：**

|      | 实例方法（-）   | 类方法（+）    |
| ---- | --------- | --------- |
| 调用前提 | 必须先创建对象   | 直接用类名调    |
| 调用方式 | `[对象 方法]` | `[类名 方法]` |
| 类比   | 用你的车去加油   | 去 4S 店问车价 |

**代码示例：**

```objc
// 类方法 — 不需要先创建对象
[User usersFromArray:array];
[NetworkManager sharedManager];
[NSURLSession sharedSession];
[UIAlertController alertControllerWithTitle:...];
[NSString stringWithFormat:@"%@", ...];

// 实例方法 — 必须先有对象
User *user = [[User alloc] init];
[user configureXXX];  // 实例方法
```

- Q: `usersFromArray:` 为什么用 `+` 而不是 `-`？
- A: 因为调这个方法之前 User 对象还不存在（正要创建它们），所以只能是类的方法。

### 1.5 @property 与 \_变量

**概念：** `@property (nonatomic, copy) NSString *userId;` 编译器自动生成三样东西：

1. 成员变量：`NSString *_userId`
2. getter：`- (NSString *)userId { return _userId; }`
3. setter：`- (void)setUserId:(NSString *)userId { _userId = [userId copy]; }`

**问答：**

- Q: `_userId` 和 `self.userId` 有什么区别？
- A: `_userId` 直接访问成员变量（绕过 setter，类内部用），`self.userId` 通过 getter/setter 访问（推荐外部用）。在 `init` 方法里推荐用 `_userId` 直接赋值，避免触发 setter 副作用。
- Q: `_userId` 是变量还是指针？
- A: 普通指针变量，和 C 语言的 `char *s` 完全一样，只是它存的是一个内存地址（指向 NSString 对象）。不能解引用 `*_userId`，而是通过方法操作它指向的对象。
- Q: 为什么系统自动生成的下划线变量名叫 `_userId`？
- A: 编译器约定——属性名前面加下划线。你写 `@property NSString *user_id;` 就生成 `NSString *_user_id;`。

### 1.6 extern 全局常量

**概念：** 声明一个常量在其他文件里定义，本文件引用它。防止手写字符串拼错。

**代码示例：**

```objc
// UserCell.m — 定义
NSString * const kUserCellIdentifier = @"UserCell";

// UserListViewController.m — 引用
extern NSString * const kUserCellIdentifier;
[tableView registerClass:[UserCell class] forCellReuseIdentifier:kUserCellIdentifier];
```

**问答：**

- Q: 为什么不直接写 `@"UserCell"`？
- A: 多处手写字符串容易拼错。`@"UsreCell"` 编译不报错，运行时找不到 Cell 直接崩溃。用全局常量 Xcode 自动补全，永不出错。

### 1.8 NSJSONSerialization

**概念：** JSON ↔ OC 对象的互译器。

```objc
// 拆包：JSON 二进制 → OC 字典
NSDictionary *dict = [NSJSONSerialization JSONObjectWithData:data
                                                     options:0
                                                       error:&jsonError];

// 打包：OC 字典 → JSON 二进制
NSData *bodyData = [NSJSONSerialization dataWithJSONObject:bodyDict
                                                   options:0
                                                     error:&jsonError];
```

**问答：**

- Q: `options:0` 是什么？
- A: 行为控制开关。`0` = 默认（返回不可变对象）。其他可选：`NSJSONReadingMutableContainers`（返回可变对象）、`NSJSONWritingPrettyPrinted`（美化排版）。
- Q: `error:&jsonError` 为什么是 `&`？
- A: 传的是 NSError 指针的**地址**（二级指针），让方法内部能修改它。C 语言类比：`someFunction(&errCode)`。
- Q: JSON 返回的数据都是字典类型？
- A: 不。`{}` → NSDictionary，`[]` → NSArray，`"hello"` → NSString，`123` → NSNumber。

### 1.9 NSError 错误处理

**概念：** 网络请求出错时传递错误信息的对象。

```objc
// 系统给的
NSError *error;  // 有值时 .domain、.code、.userInfo 包含错误详情

// 自己造的
NSError *myError = [NSError errorWithDomain:@"NetworkManager"
                                       code:-1
                                   userInfo:@{NSLocalizedDescriptionKey: @"服务器未返回数据"}];
```

**问答：**

- Q: `error.localizedDescription` 和直接打印 `error` 有什么区别？
- A: `NSLog(@"%@", error)` 输出完整结构（domain、code、userInfo 全显示），`.localizedDescription` 只提取人类可读的那一句话。
- Q: `NSLocalizedDescriptionKey` 是什么？必须用吗？
- A: 苹果约定的标准 key。用这个 key 存文字，`error.localizedDescription` 才能读到。不是硬性规定，但不用的话调用方拿不到描述文字。
- Q: `code:-1` 为什么是 -1？
- A: 随意定的，只是区分"这个错是我们自己造的"。系统错误码一般用正数或 -1000 系列，自定义用负数不会冲突。

### 1.10 URL 编码

**概念：** 中文和特殊字符不能直接出现在 URL 里，必须先转码成 `%XX` 格式。

```objc
NSString *encodedName = [name stringByAddingPercentEncodingWithAllowedCharacters:
                         [NSCharacterSet URLQueryAllowedCharacterSet]];
// "张三" → "%E5%BC%A0%E4%B8%89"
```

**问答：**

- Q: 为什么需要编码？不编码会怎样？
- A: URL 有严格的字符限制，中文是非法字符。不编码 URL 构造失败，请求发不出去。
- Q: 纯数字需要编码吗？
- A: 不需要。`2` 和 `30` 是合法 URL 字符，直接拼上就行。只有中文和特殊符号才会被转成 `%XX`。

### 1.11 三目运算 vs OC 简写 `?:`

```objc
// 标准三目：条件 ? 真值 : 假值
int result = (score >= 60) ? @"及格" : @"不及格";

// OC 简写：左边不是 nil 就用左边，否则用右边
NSString *msg = responseDict[@"message"] ?: @"未知错误";
// 等价于：responseDict[@"message"] != nil ? responseDict[@"message"] : @"未知错误"
```

### 1.13 instancetype vs id vs NSInteger vs NSString

```objc
// instancetype — 返回值类型和调用者一致（用于 init 和类方法）
+ (instancetype)sharedManager;  // 调 [NetworkManager sharedManager] 返回 NetworkManager*

// id — 万能指针，指向任何 OC 对象
id something = responseDict[@"code"];  // 可能是 NSNumber

// NSInteger — 基本类型，不是对象
NSInteger code = [responseDict[@"code"] integerValue];  // NSNumber → NSInteger 必须转

// NSString — 对象类型
NSString *msg = responseDict[@"message"];  // 直接赋值，不需要转
```

- Q: `NSInteger code = responseDict[@"code"]` 为什么不行？
- A: `responseDict[@"code"]` 返回 id 指针，`NSInteger` 是基本类型，不能存指针。必须用 `integerValue` 把 NSNumber 的值取出来。

### 1.14 \_Nullable 标注

**概念：** 纯编译器提示，运行时完全无影响。`NSData * _Nullable data` 告诉编译器这个参数可能为 nil。

- Q: 有时候写有时候不写，有区别吗？
- A: 运行时没区别。它是给 Swift 看的（翻译成可选类型），OC 里所有对象指针默认都可以为 nil。现阶段不需要纠结。

### 1.15 指针类型与内存模型

**概念：** 整个程序里数据实体从头到尾只有一份。所有地方通过指针指向同一块内存，全程不复制对象。

```
服务器 JSON → NetworkManager 解析 → [[User alloc] init] → 一次内存分配
                                                            (userId=@"1", name=@"张三", age=@"25")

self.users[0] ──指向──▶ 这块内存
cellForRowAtIndexPath 里的 User *user ──指向──▶ 同一块内存
[cell configureWithUser:user] ──指向──▶ 同一块内存
```

**指针类型决定编译器视角：**

```
User *user = self.users[0];     // User * 类型
user.name;                       // ✅ 编译器知道 User 有 name 属性

id something = self.users[0];   // id 万能指针（没类型）
something.name;                  // ❌ 编译器不知道 id 有什么属性，报错
```

同一个对象，用不同类型指针去看——数据没变，变的是编译器允许你做什么。

**问答：**

- Q: 也就是说，用其他类型的指针依然可以指向这块数据，但是无法提取出内容？
- A: 对。绝大多数时候毫无意义。`id` 唯一有用的场景是充当"万能快递箱"——传递阶段不关心内容，只负责把对象递出去：`typedef void (^Block)(BOOL, id result, ...)`，调用方拿到后再强转成具体类型 `NSArray<User *> *users = (NSArray<User *> *)result;`。
- Q: OC 里 `NSString *` 和 C 语言里的指针是同一种东西吗？
- A: 完全相同——都是变量，存的都是内存地址。`NSString *_userId` 就是 `char *_userId` 的 OC 版本。区别是 OC 不让你 `*解引用`，而是通过属性和方法去操作它指向的对象。

### 1.16 alloc + init 的完整流程

**概念：** `[[User alloc] init]` 不是一步，是两步。alloc 画地盘、填零，init 装数据。

```objc
User *user = [[User alloc] initWithDictionary:dict];
```

**第一步：`[User alloc]`**

系统在堆上划一块内存，尺寸刚好好装下一个 User 对象。因为头文件里写了三个 @property，编译器自动生成了 `_userId`、`_name`、`_age` 三个成员变量。alloc 时这已个变量的位置已经被卡住了，值都是 nil（空箱子）。

```
新内存：
┌──────────────┐
│ _userId: nil │  ← @property userId 自动生成的
│ _name:   nil │  ← @property name 自动生成的
│ _age:    nil │  ← @property age 自动生成的
└──────────────┘
↑
self 指向它
```

**第二步：`initWithDictionary:dict`**

`self = [super init]` — 让父类 NSObject 做基础初始化（isa 指针、引用计数等），几乎不可能省略。然后 if (self) 里从字典取数据填进空箱子。

**完成后：**

```
┌──────────────────┐
│ _userId: @"1"     │
│ _name:   @"小明"   │
│ _age:    @"25"    │
└──────────────────┘
→ return self（把填好数据的对象返回给调用方）
```

**问答：**

- Q: 三个空箱子是默认存在的吗？为什么？
- A: 因为 `@property` 声明 → 编译器自动生成 `_变量`。alloc 时这三个变量位置就预留好了，值全是 nil。initWithDictionary: 的任务就是填它们。
- Q: `return self` 之后数据怎么回到调用方？
- A: 调用方 `User *user = [[User alloc] initWithDictionary:dict]`，`user` 指针指向这块填好的内存。然后 `[users addObject:user]` 把这个指针存入数组。数组不存数据本身，只存指针。

## 二、网络层 — NSURLSession

### 2.1 HTTP 请求基础

#### 请求结构

```
┌──────────────────────────────┐
│  请求行：GET /user/users HTTP/1.1
├──────────────────────────────┤
│  请求头（Header）：            │
│    Content-Type: application/json  ← 告诉服务器 Body 格式
│    Accept: application/json        ← 告诉服务器我要的格式
├──────────────────────────────┤
│  请求体（Body）：              │
│    {"name":"张三","age":"25"} ← 真正要提交的数据（GET 没有 Body）
└──────────────────────────────┘
```

#### GET vs POST

|      | GET                   | POST                                  |
| ---- | --------------------- | ------------------------------------- |
| 数据位置 | 拼在 URL 后面             | 放在 HTTP Body 里                        |
| 类比   | 图书馆查资料                | 银行汇款                                  |
| 请求对象 | 不可变 `NSURLRequest` 也行 | 必须 `NSMutableURLRequest`（要改方法和加 Body） |
| 参数   | `?key=val&key=val`    | JSON Body                             |

**问答：**

- Q: 请求头是什么？请求体是什么？
- A: 类比寄信——Header 是信封上的标签（格式、身份），Body 是信封里装的信纸（真正的数据）。GET 没有 Body（数据在 URL 上），POST 有 Body。
- Q: `Content-Type: application/json` 是固定的吗？
- A: 字段名 `Content-Type` 是 HTTP 协议规定。值 `application/json` 是标准格式。其他常见值：`application/x-www-form-urlencoded`（表单）、`multipart/form-data`（文件上传）。
- Q: 为什么只有新增用 POST，修改和删除用 GET？
- A: 这台服务器的设计选择，不是规定。标准 RESTful 设计是：GET 查、POST 增、PUT 改、DELETE 删。但实际服务器可能用 GET 实现所有操作（方便浏览器测试）。客户端照接口文档写就行。
- Q: URL 参数格式 `?id=2&name=张三&age=30` 为什么这么写？
- A: HTTP 协议硬性规定：`?` 开头表示参数列表，`&` 分隔多个参数，`=` 连接参数名和值。全世界网站都这么写。

### 2.2 NSURL / NSURLRequest / NSMutableURLRequest

```objc
// NSURL — 把字符串变成网址对象
NSURL *url = [NSURL URLWithString:@"http://10.17.66.196:8086/user/users"];

// NSURLRequest — 封装 HTTP 请求（不可变）
NSURLRequest *req = [NSURLRequest requestWithURL:url];

// NSMutableURLRequest — 可变请求（可改方法、加头、加 Body）
NSMutableURLRequest *req = [NSMutableURLRequest requestWithURL:url];
req.HTTPMethod = @"POST";
req.timeoutInterval = 30.0;
[req setValue:@"application/json" forHTTPHeaderField:@"Content-Type"];
req.HTTPBody = bodyData;
```

**问答：**

- Q: GET 也能用 `NSMutableURLRequest` 吗？
- A: 能，完全一样。用不可变纯粹是习惯——不需要改就不用可变的，防止无意间改坏。
- Q: `HTTPMethod = @"GET"` 写不写都一样？
- A: 对，默认就是 GET。显式写上去是代码自注释——一眼知道这是 GET 请求。
- Q: `timeoutInterval = 30.0` 有什么作用？
- A: 服务器挂了或网络断了，请求会永远卡住。超时 30 秒没回复就自动放弃，触发 error 回调。

### 2.3 NSURLSession + NSURLSessionConfiguration

**概念：** NSURLSession（快递公司）管理所有网络任务。Configuration 是创建时的配置单。

```objc
// 不带 delegate 的 session — 回调走 Block
NSURLSessionConfiguration *config = [NSURLSessionConfiguration defaultSessionConfiguration];
config.timeoutIntervalForRequest = 30.0;
_session = [NSURLSession sessionWithConfiguration:config];

// 带 delegate 的 session — 回调走代理方法（下载必须用）
_downloadSession = [NSURLSession sessionWithConfiguration:downloadConfig
                                                 delegate:self
                                            delegateQueue:[NSOperationQueue mainQueue]];
```

**问答：**

- Q: 为什么需要两个 session？
- A: 普通请求（GET/POST）用 Block 回调更简单；下载必须用 delegate 才能监听进度。一个 session 要么有 delegate 要么没有，不能混用。
- Q: `delegateQueue:[NSOperationQueue mainQueue]` 是什么？
- A: 代理方法在哪个线程执行。设主线程的好处是代理方法里可以直接更新 UI，不用写 `dispatch_async`。

---

### 2.4 dataTaskWithRequest（GET / POST 核心流程）

**8 步固定骨架：**

```
1. 构造 URL
2. 创建 NSMutableURLRequest + 设 HTTPMethod + 设超时
3. 设请求头（POST 才需要 Content-Type）
4. 装 Body（POST 才需要）
5. 创建 NSURLSessionDataTask + completionHandler Block
6. Block 里四层错误检查：网络错误 → 空数据 → JSON 解析错误 → 业务状态码
7. dispatch_async 回到主线程调 completion
8. [task resume] ★ 千万别忘！
```

**问答：**

- Q: `dataTaskWithRequest:completionHandler:` 的 Block 什么时候执行？
- A: 创建 task 后不执行，`[task resume]` 后才发请求。等服务器回复到了，系统自动触发 Block。数据回来之前代码继续跑，界面不卡。
- Q: `[task resume]` 为什么必须写？
- A: task 创建后默认是**暂停**状态，不 resume 永远不会发请求。忘了也不会报错，是无声 bug。
- Q: 网络回调在哪个线程？
- A: 后台线程。所以必须 `dispatch_async(dispatch_get_main_queue(), ^{...})` 回到主线程再更新 UI。AFNetworking 默认帮你在主线程回调，原生 NSURLSession 必须手动切。
- Q: 后台线程执行时主线程在干嘛？
- A: 主线程不等待，继续刷屏幕（每秒 60 帧）、响应触摸、播放动画。网络那 1~3 秒它能刷新 180 帧画面，所以界面流畅不卡。
- Q: `_Nullable` 写不写有区别吗？
- A: 运行时没区别。纯编译器提示。

---

### 2.5 NSURLSessionDownloadTask + Delegate

**概念：** 下载专用 Task，数据直接写硬盘（不爆内存），支持断点续传和进度回调。

```objc
// 创建下载任务（只需 URL，不需要 request）
NSURLSessionDownloadTask *task = [self.downloadSession downloadTaskWithURL:url];
[task resume];
```

**三个代理方法：**

```objc
// ① 进度回调（下载中反复调）
- (void)URLSession:downloadTask:didWriteData:totalBytesWritten:totalBytesExpectedToWrite:

// ② 完成回调（文件在临时目录，需移到 Documents）
- (void)URLSession:downloadTask:didFinishDownloadingToURL:

// ③ 出错回调
- (void)URLSession:task:didCompleteWithError:
```

**问答：**

- Q: DataTask 和 DownloadTask 有什么区别？
- A: DataTask 数据存内存（小数据 OK，大文件爆内存）；DownloadTask 数据边下边写硬盘，支持进度回调，支持断点续传。
- Q: 为什么下载不需要 NSURLRequest？
- A: 下载永远是 GET，不传参数、不改请求头、不变 Body。系统给最简 API：`downloadTaskWithURL:`。
- Q: 三个代理方法怎么被调用的？
- A: `delegate = self` 设好后，session 下载过程中自动按协议方法名找到你的方法并调用。和 `tableView.dataSource = self` 同一个机制。
- Q: 为什么 Xcode 不自动补全这三个方法？
- A: NSURLSessionDownloadDelegate 里的方法是可选的（optional），Xcode 对可选方法不积极补全。
- Q: `didWriteData` 里的 `progress` 是哪来的？
- A: 自己算的局部变量。`double progress = totalBytesWritten / totalBytesExpectedToWrite`。
- Q: `totalBytesExpectedToWrite <= 0` 跳过是什么意思？
- A: 服务器没告诉你文件多大，跳过一次进度显示（不下取消），下载本身照样跑。

### 2.6 四层错误检查

```
第 1 层：error != nil       → 网络问题（没网、超时、DNS 失败）
第 2 层：data == nil        → 返回空数据
第 3 层：JSON 解析失败       → 服务器返回的不是 JSON
第 4 层：code != 200        → 业务层面的失败
```

**问答：**

- Q: data 为空的错误为什么要自己造 NSError？
- A: 网络请求成功了（系统 error = nil），但服务器返回内容为空，系统的 error 帮不上忙，自己造一个传回去。
- Q: HTTP statusCode 和 data 里 JSON 的 `code` 是同一个吗？
- A: 不是。`response.statusCode` 是 HTTP 协议层的（快递单号）；`responseDict[@"code"]` 是 JSON 里服务器自己写的业务状态码（包裹里纸条的内容）。

### 2.9 ID 路径匹配原理

**概念：** "update"和"delete"不是系统关键字，只是路径名。服务器通过路径匹配决定执行什么操作。

### 3.2 Cell 注册与复用

```objc
// ① 注册：告诉 TableView "UserCell 类型，暗号是 kUserCellIdentifier"
[tableView registerClass:[UserCell class] forCellReuseIdentifier:kUserCellIdentifier];

// ② 复用：从回收池拿 Cell（没���就自动创建）
UserCell *cell = [tableView dequeueReusableCellWithIdentifier:kUserCellIdentifier
                                                 forIndexPath:indexPath];
```

**问答：**

- Q: Cell 复用机制是怎么回事？
- A: 1000 条数据 ≠ 1000 个 Cell。屏幕上只有十几个 Cell 循环滚——滚出屏幕的扔回收池，滚入屏幕的从回收池捞出来换新数据。
- Q: 注册和复用的暗号必须一致？
- A: 对。注册时说"暗号是 A"，复用时也报暗号 A，系统内部查表找到对应 Cell 类型。暗号不一致 → 找不到 → 崩溃。
- Q: Cell 什么时候被创建？哪行代码创建的？
- A: `dequeueReusableCellWithIdentifier:` 时，系统发现回收池没空闲 Cell → 自动调 `initWithStyle:reuseIdentifier:` 创建新的。你不需要手动 `alloc init`。

### 3.3 自定义 Cell（UserCell）

```objc
// 重写系统指定初始化器
- (instancetype)initWithStyle:(UITableViewCellStyle)style
              reuseIdentifier:(NSString *)reuseIdentifier {
    self = [super initWithStyle:style reuseIdentifier:reuseIdentifier];  // 让父类先初始化
    if (self) {
        [self setupSubviews];  // 创建自己的三个 Label
    }
    return self;
}

// 填充数据（由外部列表页面调用）
- (void)configureWithUser:(User *)user {
    self.idLabel.text = [NSString stringWithFormat:@"ID:%@", user.userId];
    self.nameLabel.text = user.name;
    self.ageLabel.text = [NSString stringWithFormat:@"%@岁", user.age];
}
```

**问答：**

- Q: 为什么必须重写 `initWithStyle:reuseIdentifier:` 而不是 `init`？
- A: 系统创建 Cell 时调用的是这个指定初始化器，不是 `init`。重写 `init` 代码不会执行。
- Q: `[super initWithStyle:...]` 什么意思？
- A: 调父类 UITableViewCell 的原始初始化，做好基础 setup（contentView、选中高亮等）。再往下做自己的定制。
- Q: 为什么三个 Label 加到 `contentView` 上而不是 `self` 上？
- A: contentView 是 Cell 内部预留的子视图容器。直接加 self 上，左滑按钮出现时内容会被挤出去。加 contentView 上系统不影响位置。
- Q: 为什么自定义 Cell，不用系统默认样式？
- A: 系统四种默认样式（Default/Subtitle/Value1/Value2）不满足需求——三个 Label 水平排列，系统样式做不到。

### 3.4 VFL 自动布局

**概念：** Visual Format Language，用字符串描述视图位置关系。

```objc
@"H:|-15-[idLabel(60)]-10-[nameLabel]-10-[ageLabel(50)]-15-|"
// H: 水平方向 | 左边距15 idLabel宽60 间距10 nameLabel自适应 间距10 ageLabel宽50 右边距15
```

- Q: `translatesAutoresizingMaskIntoConstraints = NO` 为什么必须写？
- A: 旧布局方式（frame）和新布局方式（Auto Layout）不能混用。写这行 = 关掉旧方式，只用新方式。
- Q: `centerYAnchor` 只设了 idLabel，其余两个怎么对齐的？
- A: VFL 的 `options:NSLayoutFormatAlignAllCenterY` 让所有视图垂直中心自动对齐，不用单独设。

### 3.5 UI 控件一览

| 控件                | 类型    | 用法                                         |
| ----------------- | ----- | ------------------------------------------ |
| UIBarButtonItem   | 导航栏按钮 | `initWithBarButtonSystemItem:` 系统自带 "+" 图标 |
| UIProgressView    | 进度条   | `progress` 属性 0.0~1.0，`hidden` 控制显隐        |
| UIButton          | 按钮    | `addTarget:action:forControlEvents:` 绑定点击  |

**问答：**

- Q: `UIAlertController` / `UIAlertView` / `UIAlertAction` 的区别？
- A: UIAlertView 已废弃。UIAlertController 统合了弹窗和菜单。UIAlertAction 是弹窗上的按钮，只用在 UIAlertController 里。
- Q: `addTextFieldWithConfigurationHandler:` 里的 Block 什么时候执行？
- A: **立即执行**（弹窗弹出之前），不是等用户操作。系统创建输入框→调用Block设属性→弹窗弹出。Block 里写的代码在弹窗出现前就跑完了。
- Q: `presentViewController:alert animated:YES completion:nil` — `YES` 和 `nil` 是什么意思？
- A: YES = 有放大出现动画，nil = 动画播完后不执行额外代码。
- Q: 弹窗必须加按钮吗？
- A: 必须。不加按钮弹窗永远关不掉，用户只能杀 App。
- Q: `systemBlueColor` 和 `blueColor` 的区别？
- A: `systemBlueColor` 支持暗黑模式自适应，`blueColor` 不支持。iOS 13 后推荐用 system 系列。
- Q: `textField.keyboardType = UIKeyboardTypeNumberPad` 可有可无？
- A: 不写弹出全键盘（用户可能输入中文/字母），写了只弹出数字键盘，从源头防错。
- Q: `downloadButton.enabled = NO` + `alpha = 0.6` 的作用？
- A: `enabled = NO` 系统层面禁止触摸（真防重复点击），`alpha = 0.6` 视觉反馈（按钮变淡告知用户不可用）。下载完成后全部恢复。

### 3.6 UISwipeActionsConfiguration（左滑操作）

```objc
// 删除按钮（红色）
UIContextualAction *deleteAction = [UIContextualAction
    contextualActionWithStyle:UIContextualActionStyleDestructive title:@"删除"
    handler:^(UIContextualAction *action, UIView *sourceView, void (^completionHandler)(BOOL)) {
        [self deleteUser:user];      // 弹确认框
        completionHandler(YES);      // 告诉系统按钮动画做完
    }];

// 编辑按钮（蓝色）

    contextualActionWithStyle:UIContextualActionStyleNormal title:@"编辑"
    handler:^(UIContextualAction *action, UIView *sourceView, void (^completionHandler)(BOOL)) {

        completionHandler(YES);

// 组装

    configurationWithActions:@[deleteAction, editAction]];
```

**问答：**

- Q: `action` 和 `sourceView` 怎么没用到？
- A: 系统每次都传三个参数，用不用是你的事。`action` 可以动态改颜色/图标，`sourceView` 可以取 Cell 位置。本项目不需要。
- Q: 按钮顺序怎么决定？
- A: 数组里第一个在最右边，第二个在左边。`@[deleteAction, editAction]` = 删除在右（最易点到），编辑在左。

### 3.7 SceneDelegate 入口配置详解

**概念：** iOS 13 起，App 的窗口创建从 AppDelegate 迁移到 SceneDelegate。核心逻辑是创建一块"地基"（UIWindow），把根视图放上去。

```objc
- (void)scene:(UIScene *)scene willConnectToSession:...
      options:... {

    UIWindowScene *windowScene = (UIWindowScene *)scene;   // 系统传的场景对象，强转类型
    self.window = [[UIWindow alloc] initWithWindowScene:windowScene]; // 创建地基，关联到当前场景
    self.window.frame = [UIScreen mainScreen].bounds;      // 地基尺寸 = 屏幕尺寸

    UserListViewController *vc = [[UserListViewController alloc] init];
    UINavigationController *nav = [[UINavigationController alloc] initWithRootViewController:vc];

    self.window.rootViewController = nav;                  // 导航控制器作为地基上的第一层
    [self.window makeKeyAndVisible];                       // 接通电源，点亮屏幕
}
```

**问答：**

- Q: `UIWindow` 是什么？是整个视图的地基吗？
- A: 对。屏幕能看到的一切都贴在这块地基上。没有 window，所有 View 无处可放。
- Q: `UIWindowScene` 是什么？为什么不需要 alloc？
- A: 场景描述符，告诉系统窗口在哪块屏幕上显示。它是系统传的参数，已经创建好了，你不需要 alloc。
- Q: `(UIWindowScene *)scene` 为什么强制转换？
- A: `scene` 参数类型是 `UIScene`（父类），编译器只知道它是 UIScene。强转成 UIWindowScene 后，才能传给 `initWithWindowScene:`。没有创建新对象，只是一个类型标签。
- Q: `self.window.frame = [UIScreen mainScreen].bounds` 这行什么意思？
- A: 把地基尺寸设成屏幕大小。`bounds` 是 `(x=0, y=0, width=屏幕宽, height=屏幕高)`。
- Q: 为什么包进导航控制器才能显示 title？
- A: UIViewController 自己没导航栏，`self.title` 设了也看不见。UINavigationController 给它装了一个带头部标题栏的外壳。
- Q: `rootViewController = nav` 是什么意思？
- A: 地基上先铺哪层。所有 page 的 push/pop（前进返回）都在这层上建起来。类比：盖楼，地基 → 一楼（导航控制器）→ 二楼（各个页面）。
- Q: `makeKeyAndVisible` 怎么就显示了？
- A: `makeKey` = 把这窗口设为主窗口（接收触摸和键盘输入），`visible` = 显示到屏幕上。这行之前，window 在内存但屏幕是黑的，这行等于"通电"。不写就什么也看不到。

#### setTitle:forState: — 按钮状态文字

```objc
[btn setTitle:@"下载文件" forState:UIControlStateNormal];    // 平时
[btn setTitle:@"下载中..." forState:UIControlStateDisabled];  // 禁用时
```

`UIControlStateNormal` = 按钮的正常/默认状态（没被按住、没被禁用）。

#### presentViewController:completion: — 弹窗出现

```objc
[self presentViewController:alert animated:YES completion:nil];
//                  弹出谁         有动画吗    弹完后干嘛
```

`completion` 是一个 `void (^)(void)` 类型的 Block，在弹窗动画完全播完后执行。本项目不需要弹窗出现后做额外操作，所以传 `nil`。这和 UIAlertAction 的 `handler` 同一个模式，只是触发时机不同——一个是动画结束，一个是用户点击。

#### numberOfRowsInSection 和 cellForRowAtIndexPath 的连接

两个方法不互相调用——都只被 TableView 调用。TableView 是中间的调度员：

```
reloadData → TableView 问 numberOfRowsInSection → 知道 3 行
          → TableView 依次调 3 次 cellForRowAtIndexPath → 拿到 3 个填好数据的 Cell
          → TableView 把 Cell 排好渲染到屏幕上
```

#### deleteUser 弹窗的流程

```
左滑 → 点"删除" → handler 里 completionHandler(YES) [按钮收起] + [self deleteUser:user]
    → deleteUser: 创建确认弹窗 → presentViewController 弹出
    → 用户点"删除" → performDeleteUserWithId: → 网络请求
    → 成功后弹 showAlert("删除成功") → fetchUsers 刷新
```

`presentViewController:` 在 handler Block 外面——它的作用是显示确认弹窗，和后续的成功提示弹窗时间点错开，不冲突。<｜end▁of▁thinking｜>

- A: 创建时 `editAction.backgroundColor = [UIColor systemBlueColor]`。写在外面 = 还没点就已经蓝了；写在 handler 里面 = 点了才蓝（但点了按钮就消失了，来不及看）。

### 3.9 视图层级全景

**完整层级链：**

```
UIWindow（地基，1 个）
  └── UINavigationController（导航壳，1 个）
        ├── 导航栏（系统自动渲染，不占页面空间）
        └── UserListViewController.view（页面，1 个）
              ├── tableView（1 个）→ 里面装着 N 个 UserCell
              │     ├── UserCell[0] → contentView → idLabel, nameLabel, ageLabel
              │     ├── UserCell[1] → contentView → ...
              │     └── ...
              ├── downloadButton（1 个，和 tableView 平级）
              ├── progressView（1 个，和 tableView 平级）
              └── progressLabel（1 个，和 tableView 平级）

UIAlertController → presentViewController 弹到最顶层，不在正常层级中
```

**关键理解：层级 ≠ 空间位置。** tableView 和 downloadButton 都在 view 上平级，VFL 布局决定谁在上面谁在下面。Cell 只存在于 tableView 内部。

**问答：**

- Q: tableView 和 Cell 是配套的吗？没有 tableView 能用 Cell 吗？
- A: 不能。Cell 是 TableView 的"员工"，离开 TableView 没有回收池、没有 index、没有滚动，只是一块空白模板。

### 3.10 Target-Action 机制

**概念：** UIKit 控件（UIButton、UIBarButtonItem 等）通过"目标对象 + 方法名"的模式绑定点击响应。不是系统"猜"到要调哪个方法，而是创建控件时你亲口告诉它的。

```objc
// UIBarButtonItem：创建时一并指定
[[UIBarButtonItem alloc] initWithBarButtonSystemItem:UIBarButtonSystemItemAdd
    target:self                                          // 收信人
    action:@selector(addUserButtonTapped)];              // 信的内容（方法名）

// UIButton：创建后再绑定
[button addTarget:self                                // target：收信人
           action:@selector(downloadButtonTapped)     // action：方法名
 forControlEvents:UIControlEventTouchUpInside];       // 触发条件
```

- `@selector(方法名)` 不是字符串，是方法名的引用。系统拿着它去 target 对象上找同名方法，找到就调。
- 类比寄信：target = 收信地址，action = 信的内容（"请执行 xxx 方法"），系统 = 邮递员。

### 3.11 Cell 复用机制深入

**复用池存什么：** 空模板——三个 Label 的框架（idLabel、nameLabel、ageLabel 已经创建并布局好了），但上面没有数据。不是存"带着"张三"这行字的完整行"。

**完整流程：**

```
① cellForRowAtIndexPath 被调
    ↓
② dequeueReusableCellWithIdentifier: → 去回收池："有 UserCell 吗？"
    ├── 有 → 拿空模板出来
    └── 没有 → 系统自动调 [[UserCell alloc] initWithStyle:reuseIdentifier:]
                → 执行你重写的初始化 → 创建三个 Label + VFL 布局 → 返回全新空 Cell
    ↓
③ [cell configureWithUser:user] → 往空 Cell 填数据
    ↓
④ return cell → 渲染到屏幕
```

**滑出→回池→再滑回来：**

```
下滑：第 0 行滑出屏幕 → Cell 扔回回收池（空架子保留，数据会覆盖）
上滑：第 0 行又出现 → 池子有 → 拿模板 → configureWithUser: 填新数据 → 显示
```

如果不调 `configureWithUser:`，屏幕上会残留上次的旧数据。每次 `cellForRowAtIndexPath` 必须调 `configureWithUser:` 确保数据是对的。

**频次说明：** 初始化（创建 Label）只在前十几个 Cell 首次出现时调一次，之后永远从池子拿模板。但填数据（configureWithUser）每次必执行。

**问答：**

- Q: `rowHeight = 60` 为什么设在 TableView 上？
- A: Cell 不决定自己多高——TableView 统一管理。就像一张长桌子，桌子说"每排座位 60cm"，不是椅子自己决定。

### 3.12 数据流转全景（JSON → 字典 → 数组 → User → Cell）

**概念：** 从服务器原始二进制到屏幕上的一行文字，数据经历的每一步都长什么样。

```
阶段 0：服务器返回原始二进制（NSData）

阶段 1：NSJSONSerialization 解析 → NSDictionary
  responseDict = @{ @"code":@200, @"data":NSArray, @"message":@"success" }
  JSON 里的 {} → NSDictionary，[] → NSArray，"" → NSString，数字 → NSNumber
  完全是 NSJSONSerialization 自动完成，不需要任何手动操作

阶段 2：responseDict[@"data"] → NSArray（里面装 NSDictionary）
  dataArray = (@{@"id":@"1",@"name":@"张三",@"age":@"25"}, @{...})

阶段 3：usersFromArray: → for-in 遍历 dataArray → 每个字典调 initWithDictionary:
  字典 @{@"id":@"1",@"name":@"张三"} → User 对象 (.userId=@"1", .name=@"张三")
  翻译完成后字典仍在原数组中，User 对象存在新数组中，两份独立内存

阶段 4：最终结果 → NSArray<User *>
  users = (<User: id=1, name=张三>, <User: id=2, name=李四>)

阶段 5：存入 self.users → reloadData → cellForRowAtIndexPath:
  [cell configureWithUser:users[0]] → idLabel.text=@"ID:1", nameLabel.text=@"张三"
```

**问答：**

- Q: `responseDict[@"data"]` 为什么取出来就是数组？
- A: 因为服务器返回的 JSON 里 data 字段的值的符号是 `[...]`。NSJSONSerialization 严格按 JSON 符号规则翻译——遇到 `{}` 就是字典，`[]` 就是数组。不需要你做任何操作。
- Q: 为什么 `usersFromArray:` 里要判断 `!array` 和 `isKindOfClass`？
- A: OC 的 `(NSArray *)` 类型声明不强制运行时检查。`nil` 和错误类型（如 NSString）都能绕过编译通过，foreach 遍历会直接崩溃。`!array` 防 nil，`isKindOfClass` 防非数组，两道防线。

## 七、易混淆概念对比

### 7.1 Block 回调 vs Delegate 代理

|       | Block 回调                      | Delegate 代理                             |
| ----- | ----------------------------- | --------------------------------------- |
| 关系    | 一对一（方法参数传 Block）              | 一对一（设 delegate = self）                  |
| 回调用法  | 网络请求结果、弹窗按钮操作                 | 下载进度、TableView 数据源                      |
| 建立方式  | Block 作为参数传进去                 | `delegate = self` + `<>` 协议声明           |
| 本项目例子 | NetworkManager 的所有 completion | 下载的三个代理方法、TableView DataSource/Delegate |
| 调用方   | 你的代码主动调 `completion(...)`     | Session / TableView 内部自动调               |

### 7.2 resume 作用

`[task resume]` = **启动网络请求**。task 创建时是暂停状态，不 resume 不工作。DataTask 和 DownloadTask 都必须写。忘了不会有编译错误，请求永远不会发出（无声 bug）。

### 7.3 NSURLSession 三种配置

| 配置                                | 特点             | 什么时候用     |
| --------------------------------- | -------------- | --------- |
| `defaultSessionConfiguration`     | 正常缓存，写磁盘       | 绝大多数场景    |
| `ephemeralSessionConfiguration`   | 不缓存，纯内存        | 隐私浏览、无痕模式 |
| `backgroundSessionConfiguration:` | 后台下载，App 关了也能跑 | 大文件后台下载   |

本项目只用 `defaultSessionConfiguration`。

### 7.4 sharedSession vs 自定义 session

|               | [NSURLSession sharedSession] | 自定义 session |
| ------------- | ---------------------------- | ----------- |
| 能不能改超时        | 不能                           | 能           |
| 能不能设 delegate | 不能                           | 能           |
| 什么时候用         | 快速测试                         | 正式项目        |

本项目改成了自定义 session = 统一配置超时 + 下载 session 有 delegate。

### 7.5 HTTP Status Code vs 业务 Code

|       | response.statusCode     | responseDict[@"code"]         |
| ----- | ----------------------- | ----------------------------- |
| 层级    | HTTP 协议层                | 业务层（JSON 里）                   |
| 来源    | NSURLResponse           | NSJSONSerialization 解析 data 后 |
| 含义    | 200=成功 404=找不到 500=服务器崩 | 200=成功（服务器自己定义的）              |
| 什么时候有 | data 收到之前就能读到           | 必须解析 data 之后                  |

### 7.6 NSURLSessionDataTask vs NSURLSessionDownloadTask

|      | DataTask               | DownloadTask           |
| ---- | ---------------------- | ---------------------- |
| 数据去向 | 内存（NSData）             | 硬盘（临时文件 → Documents）   |
| 大文件  | 内存爆炸 ❌                 | 边下边写 ✅                 |
| 进度回调 | 无                      | 有（delegate）            |
| 断点续传 | 不支持                    | 支持                     |
| 创建方式 | `dataTaskWithRequest:` | `downloadTaskWithURL:` |
| 用于   | GET / POST 请求          | 下载文件                   |

### 7.7 OC 三目 `?:` vs 标准三目 `? :`

```objc
// 标准三目（C 语言通用）
condition ? valueIfTrue : valueIfFalse;

// OC 简写（OC 独有）
value ?: fallbackValue;
// 等价于：value != nil ? value : fallbackValue
```

`?:` 只判断 nil，不判断其他条件。
